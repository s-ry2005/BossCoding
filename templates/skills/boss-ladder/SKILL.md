# 四阶梯：从想法到上线

总原则：先给老板看见可用产品，再补真正需要的基础设施；花钱或等待审批的事项，等需求出现再提。触发前绝口不提下一阶，触发后一次只推进一步。全程按 `AGENTS.md` 的导师模式说话，并先运行命令探测真实状态。

## 第 0 阶・开工

第一次对话时只问「你想做个什么？」，陪老板把 `AGENTS.md` 开头填成三句大白话，然后立刻做最小可用的第一版。能预览就由 AI 启动并直接打开，再交验收单；不提 GitHub、域名、服务器或备案，也不让老板先选技术方案。

## 第 1 阶・GitHub：第一版验收后再上保险

- 只有第一版已经打开给老板看，并且老板明确验收通过后，才提 GitHub。此前不以「趁我干活先注册」打断第一次正反馈。
- 用大白话说明：「GitHub 是代码的网上保险柜，免费。现在东西已经值得保存；如果你愿意，我带你注册并把剩下的步骤办完。」注册通常约十分钟；账号和授权由老板本人确认，注册不顺也不阻塞继续开发。
- 老板同意后，AI 建私有仓库、连接并首次上传。优先使用 GitHub 官方登录流程；涉及账号授权时停下来等老板确认，其余步骤由 AI 完成。
- 连接后，每次改动正式送检时会在 GitHub 自动检查，本机保护会防止常见的误操作。免费私有仓库的云端检查不一定能硬性拦住网页合并，因此不能承诺「检查不通过就绝对进不去」；AI 必须只在检查通过后合并。
- 从连接成功起，改动留在任务分支，通过改动申请完成合并，不再先合进本地稳定分支。并行任务用项目选定的包管理器执行 `bosscoding merge`，判断顺序。
- 下一步只给老板一句自然语言，例如：「你只需要回：带我把代码备份到 GitHub。」不要让老板执行命令或清理工作区。
- 用 `git remote -v`，并用项目选定的包管理器执行 `bosscoding status` 探测当前状态；查不到远端真实结果时说「暂时无法确认」，不把未知说成已备份。

## 第 2 阶・服务器

触发条件是老板说「给朋友用」「发给别人看看」或「对外」。

1. 先问一句：「使用的人主要在国内还是海外？」答案决定服务器位置，也决定下一阶是否需要网站备案；把结论记进决策档案。
2. 给一个最本质的选择：国内默认轻量服务器，海外选新加坡或美西节点。价格通常约 ¥99～199／年；花钱是红线，算清价格并等老板确认，由老板本人下单。
3. 下单后由 AI 完成密钥、运行环境、部署和自动启动。完成后直接给可打开的地址，并说明这是一串临时数字网址，适合试用。
4. 部署属于产品自己的上线流程，BossCoding 的自动检查不会替它上线。第一次部署时，把「以后由谁触发上线」写入决策档案。

## 第 3 阶・域名与加密访问

触发条件是老板说「想要自己的网址」或「想正式一点」。

- 国内用户：注册域名（通常几十元／年）→ 立即提交网站备案（法定流程，通常约一到两周）→ 通过后由 AI 连接域名并配置加密访问。等待期间仍可用临时地址试用和继续开发。
- 海外用户：直接连接域名并配置加密访问，不需要网站备案。

## 跳级与到顶

- 老板一开始就明确要正式上线时，主动说明是否应提前准备服务器和域名；仍然要把价格、等待时间和风险讲清，并逐项等确认。
- 纯本地工具不需要服务器或域名。想分发给别人属于对外发布，按红线先说明并等确认。
- 每次只给一个老板下一步，而且必须是一句自然语言；不要把命令、路径或工作区清理交给老板。
