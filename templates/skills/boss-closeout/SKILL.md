# BossCoding 完整收尾

先完整阅读项目根目录 `AGENTS.md`，以当前代码、运行态和真实入口为准。旧文档、CI 绿、部署命令退出 0、接口可连接均不是用户已拿到可用结果的证据。

## 状态契约

状态只能按此顺序推进，彼此不自动推导：`merged → deployed → live-verified → knowledge-closed → reported → cleanup-approved → cleaned → done`。没有部署目标的项目把 `deployed` 和 `live-verified` 标为 `not-applicable`；任何无法核实的状态标为 `pending`，并说明阻碍和下一步。

## 部署与真实验证

1. 核对稳定分支、部署版本标识、真实入口和部署时间；部署、对外发布、花钱、权限或密钥属于红线时先取得用户确认。
2. 直接通过真实线上入口完成至少一条核心用户路径，记录版本标识、入口、路径、本次改动结果和时间。网页必须看实际页面，不能只读日志。
3. 验证失败先修复或按保留历史的方式撤销；不得把 CI 绿、部署命令退出 0 或接口连通报告为 `live-verified`。

## 知识收尾与汇报

1. 调用 `neat-freak`；若不可用，完成代码、运行态、文档、规则、获准维护的记忆、工作区六面等价审计，并明确报告没有调用原技能。
2. 只用已验证事实同步受影响的正式文档和规则；记忆只有在平台和用户授权允许时更新。重大长期裁决只追加进 `docs/decisions/`。
3. 复盘只记录真实发生且可复用的经验；没有新经验可以写“无”。
4. 输出完整报告：用户结果、每个状态、验证证据、知识变更、pending/out-of-scope、候选清理对象；完成 `reported` 后保留现场。

## 确认后清场

1. 清理前逐项列出分支、worktree、能证明由本任务创建的临时数据库和临时产物，说明归属、影响和恢复方式。归属不明的数据库标为 `pending`。
2. 任务开始时的“做完清理”不算确认。只有用户在完整报告后明确确认，才进入 `cleanup-approved`。
3. 禁止删除未合并、未提交、无法恢复或归属不明的对象。确认后才清理精确对象，并重新审计。
4. 报告实际清理项与复查结果；全部适用项通过才标记 `cleaned` 和 `done`。
