# 以独立 scoped 包发布 fork，并区分框架维护状态

## 影响

这个 fork 需要让新产品用一条 npm 命令安装增强流程，同时框架仓库自身运行 `status` 不能因未安装产品资产而误报红色。

## 根因

上游公开包名 `bosscoding` 属于原作者；fork 不能发布同名包。此前 README 只能要求克隆仓库并填写本机路径，而 `status` 把模板源仓库当作已经初始化的产品项目检查。

## 裁决

发布为公开 scoped 包 `@s-ry2005/bosscoding`，保留 `bosscoding` 命令名。`init` 为新项目写入当前发布包名，`update` 同时兼容旧的未 scoped `bosscoding` 依赖。框架源仓库识别为维护模式，只检查模板、CI 和测试入口；产品项目仍检查已安装的 hooks 与技能。

## 被否决的方案

继续使用 `file:` 本机路径会让每个新项目依赖固定电脑路径。把 hooks 与技能安装到框架仓库会混淆模板与产品副本。覆盖上游的未 scoped 包名既不可行，也会误导原版用户。

## 不变量

公开发布前必须经过 PR、CI、老板确认和可信发布；npm 私有包、权限、密钥和自动部署均不引入。`status` 保持只读，且产品项目缺少或篡改已安装资产时仍不得亮绿。
