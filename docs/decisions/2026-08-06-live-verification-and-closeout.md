# 完整交付加入线上验证、知识收尾与确认式清场（2026-08-06）

## 影响

- 之前：BossCoding 的交付主要止于合并，线上真实效果、知识同步和清理确认容易落在人的记忆里。
- 之后：交付有可报告的八个状态；无法验证不报完成，清理只在用户确认后发生。

## 根因

`boss-flow` 负责开发和合并，`boss-ladder` 负责何时需要基础设施，但没有一个可复用入口把部署后的真实验证、六面知识审计、汇报和确认式清场连起来。

## 裁决

**新增托管 `boss-closeout`，由 `boss-flow` 和 `boss-ladder` 路由进入。**它只规定部署后的验证和收尾契约，不提供通用部署方案；安装、更新和状态检测将它与现有托管技能同等处理。

## 被否决的方案

**把通用 deploy workflow 加入 CI**：不同项目的部署方式、密钥和权限不同，通用猜测会扩大 CI 权限并触碰红线。

**把完整步骤塞入 AGENTS.md**：会破坏规则简短、操作细节放技能的既有知识纪律。

**合并后自动清理**：合并不能证明线上可用、知识已同步或对象可恢复，误删代价高于节省的时间。

## 不变量

1. CI 仍只做质检，不增加部署权限、通用部署脚本或自动删除命令。
2. `live-verified` 必须有真实入口、版本、用户路径、改动结果和时间的证据。
3. `neat-freak` 不可用时必须报告并做六面等价审计；记忆更新服从平台和用户授权。
4. 清理必须晚于完整报告和用户明确确认；未合并、未提交、归属不明或无法恢复对象永不删除。
